Method and interpretation

The workflow uses Goodfire's branch enumeration and probability-weighted outcomes, then its mixture-draw construction and segment-kernel reconstruction. Each pass is fitted separately. Cross-validation uses only that pass's samples.

Changing models does not reproduce the published numerical results. PELT boundaries are candidate changes between observations; they do not identify a causal token. Credible bands are model-based and can be miscalibrated. A separate dense run permits comparisons without reusing the fitting continuations.

Muse uses its native image/text model loader and text-only chat template. Other compatible models must load with Hugging Face AutoModelForCausalLM and safetensors, fit this runtime, and provide distinct single-token A–D answer labels. Muse answers are read only from completed user-facing channels; unfinished replies count as Other. This version uses standard batched generation, without the cross-branch prefix-cache speedup. No custom model code is executed.
